# loom 记忆增强型 Agent 框架实现方案

日期：2026-10-28  
状态：已在 `loom` 完成命名空间改造及首个 MemAgent 运行路径；通过离线语义测试，完整 GPU 训练兼容性尚未验证。

## 1. 问题与目标

现有 memRL 工作往往将记忆定义、Agent 工作流、数据格式、奖励和训练实现绑定到单一任务，导致代码难懂、实验难复现、方法难横向比较。

loom 的目标是提供一个面向记忆增强型 Agent 的模块化训练与推理框架：统一描述不同记忆方法，复用成熟的模型训练和推理基础设施，让研究者主要实现记忆机制、Agent 编排、任务与评测。

框架应支持两类实验：

- **原方法复现**：保留原论文的控制流程、模型、数据处理、奖励和预算，明确记录实现差异。
- **统一条件比较**：控制模型、数据划分、评分器与预算，比较不同记忆机制的效果及成本。


## 2. 主要决策：基于 skyrl-agent 的骨架做记忆特化

### 当前采用的代码位置与实现进展

根据新的目录安排，以 `loom/` 为 loom 自己维护的运行包，Python 包名为 `loom`；原实现位于根目录 `loom_agent/`。根目录的 `skyrl-agent/` 保留为参考副本，不作为新的开发或安装入口。

已新增独立文本记忆模块、固定编排 MemAgent、记忆任务与数据转换、采样轨迹适配和原生 SkyRL 训练入口。现有配置、Dispatcher、Transition 及后端适配优先复用，新的 MemAgent 路径不复制旧集成 Trainer 的完整训练循环。Memory-R1 和 RMM 尚未迁移。

具体使用方式与验证边界见 [运行包说明](../loom/README.md)，来源见 [UPSTREAM.md](../loom/UPSTREAM.md)。下文保留设计目标；已有实现不代表所有阶段均已完成。

原 `SkyRL/skyrl-agent` 与根目录 `skyrl-agent/` 保留用于源码对照。实际开发和安装使用新的 `loom` 命名空间，配置中的动态类路径也已同步修改。安装入口是根目录 `pyproject.toml`；不要求手动同步多份源码。

轻量流程已经通过离线测试。训练建议使用独立 Python 3.12 环境；真实模型采样、GPU 后端和依赖版本仍需在阶段 A 验证。

具体边界：

- loom 保持为主项目，承载记忆方法、配置、实验与评测。
- 运行逻辑以 `skyrl-agent` 为基础，优先复用其 Runner、调度、轨迹处理和后端集成。
- 不继续将现有 `loom_agent/trainers/mem_grpo_trainer.py` 扩展为主要分布式训练引擎。
- 不同时维护两套采样展开、异步调度、优势计算、训练批次处理和权重同步逻辑。
- “主要改 Agent 层”包含其必要的任务、状态和评测扩展，不意味着所有改动只能发生在 `agents/` 目录。

这是对 `skyrl-agent` 的记忆领域特化，不是把其代码重新命名后作为独立的基础设施贡献。论文与文档应清楚说明复用来源，以及 loom 新增的记忆抽象、方法复现和比较能力。

## 3. 复用范围与改造范围

| 部分 | 第一版处理方式 | 边界 |
|---|---|---|
| `skyrl_agent/config/` | 复用；有实际需要时扩展字段 | 保留轨迹配置，增加记忆容量、状态范围等实验配置 |
| `skyrl_agent/dispatcher/` | 直接复用 | 负责并发与生命周期调度，不负责记忆方法决策 |
| `skyrl_agent/functional/` | 优先复用 | 记录模型调用、处理消息和训练片段；验证上下文重置后的语义 |
| `skyrl_agent/integrations/` | 保留结构，先验证 SkyRL 一条路径 | 不承诺所有后端、算法均可直接兼容 |
| `AgentRunner` | 优先复用 | 统一进行多轨迹展开、调用调度器、汇总输出 |
| Agent / Trajectory | 新增记忆专用实现 | 负责记忆策略与完整任务尝试 |
| `tasks/` | 复用基类，新增记忆任务适配 | 数据读取、初始条件、任务完成和评分 |
| `tools/` | 按方法需要使用 | 自主工具调用是可选流程，不能强制替代原方法的固定编排 |
| loom 现有记忆逻辑 | 提取可复用行为，逐步迁移 | 保留提示词、解析和算法顺序，移出训练引擎职责 |
| loom 现有 Trainer | 暂保留历史入口，退出新主链路 | 新路径不再调用它计算损失或更新参数 |

必要时以小补丁修复公共层实际缺口，避免为记忆框架再建一套等价的 Runner、Dispatcher 或训练后端抽象。

## 4. 目标运行链路

```text
实验启动配置
    ↓
SkyRL 集成入口 / Trainer
    ↓
skyrl-agent Generator → AgentRunner
    ↓
Dispatcher：初始化 → 执行 → 评估
    ↓
loom MemoryTrajectory
    ├── Task：任务数据、初始记忆、评测
    ├── MemoryAgent：固定流程或自主决策
    ├── 记忆模块：提取、更新、检索、压缩等
    ├── MemoryState / Store：本轨迹的记忆状态
    └── 已有推理适配器 → 当前策略或固定模型
    ↓
真实输入输出 token、mask、奖励、任务和轨迹关系
    ↓
已有轨迹转换与训练集成
    ↓
后端计算优势、损失、梯度，更新参数并同步采样权重
```

推理与训练使用同一套记忆流程。推理时不执行参数更新；若训练与推理使用不同服务，只替换模型调用实现和采样配置，不另写一套记忆算法。

## 5. 各层责任

### 5.1 MemoryAgent：决定记忆操作顺序

负责组织模块调用，而不直接接收本地 PyTorch 模型、计算优势或打包 GPU 张量。

先支持已有方法需要的两种控制方式：

- **固定编排**：代码规定读取、提取、更新、检索、回答的顺序。
- **自主编排**：策略通过工具调用决定下一步操作。

两种方式共享记忆模块与记录机制。将固定 MemAgent 流程改成 ReAct 工具选择，会改变原方法，必须作为独立实验设置。

### 5.2 MemoryTrajectory：管理一次完整尝试

优先遵循现有生命周期：

```python
initialize_trajectory()
generate_trajectory()
evaluate_trajectory()
```

负责：

- 创建或恢复本次尝试的记忆状态。
- 运行 Agent，记录各阶段实际看到的输入与生成的输出。
- 收集终局结果、原始奖励、错误和资源消耗。
- 正常结束或异常退出时清理状态。

一条轨迹可以包含多个独立上下文下的模型调用。轨迹本身不等同于一段不断增长的聊天文本。

### 5.3 记忆模块：可组合的领域行为

优先迁移现有提取、更新、检索、重排和循环压缩逻辑，不先建立复杂的通用工作流引擎。

模块负责输入构造、生成结果解析和记忆操作；模型调用通过注入的已有推理接口完成。

第一版保留“同一个可训练策略在多个阶段被调用”以及“部分阶段使用固定模型”两种情况。

### 5.4 MemoryState / Store：明确状态范围

统一状态生命周期，而不强制所有方法使用同一个物理表示。

- MemAgent 可以是文本记忆。
- Memory-R1 可以是带 ID 的结构化条目。
- RMM 可以结合记忆条目、向量检索和候选选择。
- 图记忆等表示按实际方法扩展，不为尚未实现的形式预建完整接口。

至少明确以下操作对应的语义：初始化、读写、复制或快照、恢复、清理。具体接口按首个方法的实际需求收敛。

并行采样同一任务的多条轨迹，应从相同初始状态各自执行；不能共享会相互修改的全局单例。可以共享数据库连接或只读索引，但写入必须按任务/轨迹隔离。

跨会话持久记忆属于显式任务设置，不能由程序进程是否重启偶然决定。

### 5.5 Task 与评测：明确任务而非绑定算法

任务提供问题、文档或事件流、初始记忆、终止条件、答案与评测方式。

数据集字段转换由任务适配完成，不让每个记忆模块直接依赖 `fact`、`context_memory`、`reward_model` 等原始字段。

任务不应把某一种记忆方法的提取、更新和检索顺序硬编码进评分函数。旧代码中这类逻辑迁入 Agent 或共享执行辅助函数，再由评测读取运行结果。

## 6. 轨迹与训练语义：必须验证的契约

复用输入输出格式之前，先检查现有 `Transition`、轨迹结果和 metadata 能否表达以下内容；能表达就复用，不另建平行格式。

| 信息 | 必须保证 |
|---|---|
| 原始任务 ID | 同一问题的多次采样可正确分组 |
| 轨迹 ID | 不同采样尝试的状态、奖励和记录互不混淆 |
| 模型调用/阶段 | 区分更新记忆、检索选择、最终回答等阶段 |
| 策略归属 | 区分可训练策略、固定 LLM、规则、工具 |
| token 与采样概率 | 使用实际生成记录；不能修改文本后继续复用错位概率 |
| 原始奖励 | 不在 Agent 中预先变成 GRPO 优势 |
| loss mask | 工具反馈和非训练策略输出不能被误当成训练动作 |
| 状态与预算 | 能解释本步骤看到的记忆、上下文和资源消耗 |

### 6.1 上下文重置

MemAgent 每次更新后可能只保留问题、当前记忆和新文档块。应记录本次真实模型输入，不为方便训练而补回已丢弃的历史。

`functional/transitions_to_training_data()` 已支持在输入不保持前缀时拆成多个训练片段。需要验证拆分后的片段仍归属于同一条采样轨迹，组内统计不能因为某条轨迹更长而重复计入多次终局奖励。

### 6.2 奖励与优势

- loom 产生任务奖励及其明确的阶段/终局归属。
- 训练后端按实验配置计算优势、KL 和策略损失。
- 将终局奖励用于多个记忆步骤时，必须沿用对应方法的训练定义。
- 不把多条独立上下文的生成错误地视为多个独立问题。
- 不在 Agent 和后端各进行一次组内标准化。

### 6.3 固定模型与可训练策略

以 RMM 为例，固定提取和更新模块的输出可以作为重排器的输入，但不能作为重排策略自己采样的动作计算策略梯度。

如果所选轨迹转换路径默认训练所有 LLM 调用，先增加最小的归属过滤或 metadata 适配，不假设已有框架天然支持多策略训练。

### 6.4 推理能力不等于训练支持

已有后端适配器对 token 接口、文本接口、采样 logprob 的支持不完全相同。任务能完成推理，不代表所有后端都能按同一算法训练。

第一版只承诺经过验证的后端、模型和训练配置组合。

## 9. 分阶段实施与验收

### 阶段 A：固定一条能运行的依赖链

工作：

1. 记录本地 loom 和所选 skyrl-agent / SkyRL commit。
2. 选择唯一的新主入口：skyrl-agent 的 SkyRL 集成。
3. 核查该入口与 Trainer、Generator、配置字段的版本匹配。
4. 固定依赖和安装来源；明确 Python、CUDA、GPU 与注意力实现要求。
5. 先完成最小生成和训练更新，不使用大模型 SWE 示例作为最低门槛。

验收：能够定位实际导入源码；一个极小任务完成采样、奖励、反向传播、权重同步与再次采样。

当前已发现的兼容点包括：旧示例使用 `fsdp2`，本地核心策略分支使用 `fsdp` / `megatron`；skyrl-agent 的后端依赖可能从远程 Git 获取，而不是旁边的本地目录。这些必须核实，不能仅修改一个配置名称就宣称解决。

### 阶段 B：迁移 MemAgent 的推理与轨迹记录

工作：

1. 实现记忆专用 Trajectory 和固定编排 Agent。
2. 迁移分块、记忆覆盖和最终回答行为，保留原提示词与长度设置。
3. 复用现有推理适配、Transition 记录和 Dispatcher。
4. 每条采样轨迹独立创建记忆状态。
5. 在不训练的情况下保存可检查轨迹。

验收：能够逐步查看每次实际输入、记忆变化、输出和评分；模型看到的上下文与既定 MemAgent 流程一致。

现有 `tools/next_memagent.py` 可作参考；只有其工具调用语义与目标配置一致时才直接采用，不能用它悄悄替换固定编排基线。

### 阶段 C：接通 MemAgent 的 RL 小实验

工作：

1. 将轨迹与原始奖励交给既有 SkyRL 集成处理。
2. 验证独立上下文拆分、mask 和组内关系。
3. 只使用一种策略模型及一套明确的优势/损失配置。
4. 完成小数据训练、checkpoint 保存与恢复、固定验证集评测。

验收：任务数、轨迹数、模型调用数和训练片段数可区分；策略参数确实更新，更新权重被后续采样使用；错误或截断不会被默认为成功。

已有 `datas/converted_hotpotqa_2000.json` 实际检查为 1990 条。应记录文件校验值和使用版本，不按文件名假定样本数，也不能把它自动视为原 MemAgent 全量训练设置。

### 阶段 D：接入 RMM，再接 Memory-R1

RMM 用于验证：相同执行基础能否支持固定提取/更新与可训练重排器共存。

Memory-R1 用于验证：提取与更新阶段能否组合、单独开启训练，并正确关联同一轨迹的奖励。

验收：切换方法不需要重写 Trainer；替换一个记忆模块不需要复制整套数据处理与评分代码；固定阶段没有进入错误的策略损失。

若只能通过增加大量方法名称判断分支才能接入第二个方法，应回到模块和任务边界调整，而不是继续叠加条件。

### 阶段 E：统一比较，再扩展后端

先完成同一后端下的方法比较，确认抽象稳定，再验证 VERL 或 Tinker 的第二条训练路径。

后端切换应验证采样字段、概率、mask、奖励分配、模型版本和checkpoint行为，不以“脚本能启动”作为兼容标准。

## 10. 测试与比较协议

### 10.1 必要的语义检查

- 两条并发轨迹修改同名记忆时互不污染。
- 上下文重置后，后续生成不再获得应被丢弃的历史。
- 模型输出 token 与采样 logprob 对齐；观察 token 不参与策略动作损失。
- 某条轨迹包含更多训练片段，不会改变原始采样组的成员数量。
- 固定模型输出不进入可训练策略的动作损失。
- Agent 输出原始奖励，后端仅按配置计算一次优势。
- 快照/恢复能重建任务规定的状态；失败轨迹按统一规则处理。

先用确定性模拟生成和小规模测试验证上述关系，再做真实模型训练；mock embedding 不用于替代正式语义检索实验。

### 10.2 实验记录

每次运行保存：

- 方法与代码版本、数据处理版本、文件校验值、训练/验证/测试划分。
- 策略、固定回答模型、embedding 与检索器版本。
- 提示词、聊天模板、采样配置、可训练阶段和模型版本信息。
- 记忆容量、上下文限制、文档截断和重置规则。
- 任务奖励、最终评测器、失败/超时处理和checkpoint选择规则。
- 生成 token、模型调用数、工具调用数、耗时及存储/检索成本。

验证集用于调参或选择checkpoint时，不将共享问题的长度变体描述成独立测试集。外推实验可以在测试集内部复用问题，但应与开发集分开。

随机种子一致不保证更换推理引擎或批次调度后逐token一致。比较以明确控制条件、重复运行和统计结果为准。

## 11. 第一版不做的事项

- 不重新实现通用多后端推理层、Dispatcher 或分布式 Trainer。
- 不同时迁移所有记忆方法、数据集和后端。
- 不要求所有记忆机制采用相同条目格式或相同物理数据库。
- 不强制所有方法改成 ReAct 工具调用。
- 不默认支持多独立策略联合优化、任意图工作流或分布式共享可变记忆。
- 不将已有工具、模块或示例的存在等同于完整论文复现成功。

## 13. 完成标准

第一版完成不是“把目录复制到 loom”，而是：

1. 固定版本的执行与训练链路确实可运行。
2. 记忆方法可以在不修改训练引擎的情况下表达和替换。
3. 同一任务的采样、记忆状态、轨迹、奖励与训练数据具有可检查的一致关系。
4. 至少 MemAgent、RMM、Memory-R1 的实际差异能够由组合配置和少量方法逻辑表达。
5. 提供可复现运行入口，以及明确区分原方法复现与统一条件比较的实验记录。

当前已完成 loom 命名空间迁移、首个 MemAgent 流程、数据转换与离线测试；Memory-R1/RMM 迁移、真实 GPU 后端兼容性、性能与完整训练结果仍需按阶段验证。
